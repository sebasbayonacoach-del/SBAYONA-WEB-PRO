# BAYONA — Dirección de producto, UX y ejecución

Fecha: 2026-09-22  
Estado: documento maestro de continuidad  
Fuente: revisión visual con comentarios 1–70 sobre la experiencia web BAYONA

---

## 1. Resumen ejecutivo

BAYONA no debe sentirse como una web con páginas sueltas. Debe sentirse como una casa/club digital premium: una experiencia guiada donde la persona entra, entiende el método, descubre valor, reclama recursos, compara planes, puede comprar o hablar por WhatsApp y termina creando su cuenta para guardar todo lo ganado.

La dirección principal queda así:

- El sitio es un recorrido, no un catálogo.
- La estética debe ser cinematográfica, sobria, de lujo deportivo, con imágenes útiles y coherentes.
- Cada página debe mantener la misma “arquitectura de casa”: header, footer, progreso, siguiente paso, asistente, wallet/recompensas y salida clara.
- Las recompensas no se entregan automáticamente por scroll: se descubren y se reclaman.
- La cuenta/dashboard es la puerta final: ahí viven regalos, recursos, productos comprados, créditos, descuentos, consultas y próximos pasos.
- BAYONA+ no debe parecer una página privada desconectada. Es una estación del recorrido y debe llevar después a tienda.

## 2. Principios no negociables

### 2.1. Una experiencia guiada

El usuario debe sentir que entra en BAYONA y Sebastián le enseña la casa. Cada sección debe responder a:

1. Dónde estoy.
2. Por qué esto importa.
3. Qué puedo hacer aquí.
4. Qué gano si interactúo.
5. Cuál es el siguiente paso.

### 2.2. Premium no significa vacío

La web puede ser oscura, minimalista y cinematográfica, pero no debe quedar pobre, plana ni repetitiva. Cada bloque importante necesita intención visual: fondo, textura, foto, mockup, folio, ticket, recibo, dashboard o tarjeta.

### 2.3. Las imágenes deben justificar su presencia

Evitar:

- Imágenes aleatorias de playa.
- Imágenes con fondo blanco que rompen el tono.
- Imágenes repetidas en varias páginas.
- Fotos pequeñas metidas dentro de cajas de texto sin intención.
- Ilustraciones/SVG flotantes que no aportan.

Buscar:

- Fondos cinematográficos integrados.
- Entrenador + persona entrenando cuando el bloque habla de acompañamiento.
- Mockups de material cuando el bloque habla de recursos, app, planes o dashboard.
- Imágenes de fitness, parkour, nutrición, recuperación, comunidad y planificación que correspondan exactamente al contenido.
- Profundidad visual: primer plano nítido, fondo difuminado, gradientes, capas, textura.

### 2.4. La comunidad como referencia visual

El bloque de comunidad tipo “COMUNIDAD · NO ESTÁS SOLO / ENTRA GRATIS…” es la referencia principal:

- Imagen grande.
- Escena humana y aspiracional.
- Texto mínimo.
- Artefacto visual claro.
- Degradado que integra texto e imagen.
- Sensación de club premium, no plantilla.

Esa lógica debe trasladarse al resto del sitio, adaptada a cada página.

## 3. Arquitectura de recorrido propuesta

Orden recomendado del viaje:

1. Entrada / bienvenida / onboarding ligero.
2. Inicio: promesa, método y primera orientación.
3. Programas.
4. Academia Parkour.
5. Comunidad.
6. BAYONA+ / app en preparación.
7. Tienda / sesiones / servicios / configurador.
8. Recursos premium gratuitos.
9. FAQ / confianza / dudas finales.
10. Cuenta / dashboard / centro de mando.

Regla importante: después de BAYONA+ el siguiente paso debe ser tienda, no una ruta muerta ni una página que parezca privada.

## 4. Sistema global de navegación

### Problema detectado

El menú superior actual se siente confuso y no siempre acompaña el recorrido. Algunas páginas parecen perder el header, el footer o el flujo. Los botones de “siguiente parada” no siempre tienen sentido. El botón/indicador “LAS INSTALACIONES” no convence.

### Dirección

El header debe ordenar la experiencia de izquierda a derecha como viaje:

- Inicio
- Método
- Programas
- Parkour
- Comunidad
- BAYONA+
- Tienda
- Recursos
- FAQ
- Mi cuenta

El botón “LAS INSTALACIONES” debe revisarse. Si no aporta valor real, sustituirlo por una etiqueta contextual más útil:

- “La casa”
- “El recorrido”
- “Siguiente parada”
- “El ecosistema”
- “Tu ruta”

No debe ser una etiqueta ornamental. Debe ayudar a saber dónde estás y hacia dónde vas.

### Criterio de aceptación

- Todas las páginas mantienen header y footer.
- Todas las páginas tienen siguiente paso coherente.
- BAYONA+ enlaza hacia tienda.
- FAQ queda al final del recorrido, no como salto incoherente al inicio.
- El usuario siempre entiende si está explorando, comprando, reclamando o entrando a su cuenta.

## 5. Sistema de progreso / línea de recorrido

### Problema detectado

La línea de progreso gusta, pero aparece cortada, distinta o incoherente según la página. A veces parece decorativa y otras funcional.

### Dirección

Crear un sistema único de progreso con variantes por contexto:

- Línea horizontal para páginas de recorrido.
- Marcadores de capítulo cuando hay varias secciones.
- Microprogreso para onboarding.
- Barra discreta para páginas largas.
- Estado de recompensas encontradas/reclamadas cuando aplique.

La línea no debe ser idéntica en todas partes, pero sí debe pertenecer al mismo sistema visual.

### Reglas

- Nunca debe verse cortada por error.
- Nunca debe competir con el título.
- Debe integrarse con el naranja BAYONA.
- Debe indicar avance real o ubicación real.
- Si no comunica nada, se elimina.

## 6. Sistema de recompensas, créditos y wallet

### Problema detectado

El widget actual de dinero/créditos se ve pobre y rompe el lujo. Además, el valor no debe aparecer automáticamente solo por hacer scroll.

### Dirección

Convertirlo en una wallet/VIP pass:

- Visual de ticket, pase, tarjeta, invitación o caja fuerte.
- Estado plegado elegante.
- Estado expandido con recompensas encontradas.
- Animación de “reclamar”.
- Historial de regalos, créditos, descuentos, sesiones o consultas.
- Indicaciones claras: encontrado, pendiente de reclamar, reclamado, usado.

### Regla de producto

El usuario debe descubrir y hacer clic para reclamar regalos. No se regalan por scroll pasivo.

### Posibles recompensas

- Crédito para primera clase.
- Descuento para un plan.
- Consulta gratuita.
- Acceso a reto 7 días.
- Acceso a reto 30 días.
- Dossier personalizado.
- Recurso premium descargable.
- Entrada a comunidad.
- Cupón simulado para tienda.

### Final de recompensa

Al reclamar suficientes piezas, se abre la puerta de crear cuenta:

> “Ya tienes material guardado. Crea tu cuenta para conservarlo y continuar desde tu centro de mando.”

Si no ha reclamado suficiente:

> “Aún quedan piezas por descubrir. Puedes crear cuenta ahora, pero si completas el recorrido llegarás con más recursos desbloqueados.”

## 7. Cuenta y dashboard como puerta final

### Problema detectado

La zona “Entrar / BAYONA OS / Today” se siente separada del sitio. Parece otra aplicación, no una continuación premium del recorrido.

### Dirección

La cuenta debe ser el cierre natural del viaje. Debe conservar la identidad visual, header/footer y sensación de casa BAYONA.

El dashboard debe mostrar:

- Recursos ganados.
- Recursos comprados.
- Plan activo.
- Créditos o cupones.
- Próxima sesión.
- Consulta pendiente.
- Comunidad.
- Progreso del reto.
- Acceso a BAYONA+ cuando esté disponible.
- Funciones bloqueadas para suscriptores.
- CTA a WhatsApp o pago cuando corresponda.

### Integraciones futuras

- Stripe/pagos.
- WhatsApp como cierre humano.
- Registro/login.
- Área privada con recursos.
- Estado de compra o suscripción.
- Asistente AI integrado.

## 8. Asistente / chat / WhatsApp

### Problema detectado

El botón actual parece un cuadrado pequeño y no comunica que haya una inteligencia o guía personal detrás.

### Dirección

Convertirlo en asistente BAYONA:

- Persona: Sebastián / coach BAYONA.
- Rol: guía de recorrido, orientación, dudas, próximos pasos.
- Si puede responder, responde.
- Si no puede responder, deriva a WhatsApp.
- Puede recordar progreso dentro de la visita.
- Puede invitar a reclamar regalos o continuar la ruta.

WhatsApp debe ser visualmente claro:

- Icono real de WhatsApp.
- Texto explícito: “Hablar por WhatsApp”.
- Diferenciar WhatsApp de chat interno/AI.

### Dirección general

- Tarjeta premium.
- Dashboard.
- Ticket.
- Producto.
- Calendario.
- Mapa de ruta.
- Recibo.

### Tipos de imagen necesarios

- Entrenador con cliente.
- Entrenamiento funcional premium.
- Parkour urbano controlado.
- Nutrición realista y elegante.
- Recuperación/movilidad.
- Comunidad entrenando.
- Escritorio/planificación con materiales BAYONA.

- Tienda/equipamiento.

### Regla de coherencia

No repetir la misma imagen para resolver páginas distintas. Cada página debe tener su mundo, pero dentro de la misma casa visual.

## 10. Home / Inicio

### Mantener

- La dirección premium oscura.
- Las mejoras de jerarquía tipográfica.
- La sensación de recorrido.

### Corregir

- Más secciones deben parecer piezas cinematográficas, no cajas aisladas.
- El bloque de testimonios necesita rehacerse.
- El sistema de valor gratuito debe concentrarse mejor.
- El wallet debe dejar de parecer un contador feo.

### Testimonios

Problemas:

- La línea de edades 34/42/45/50 no aporta suficiente.
- Los testimonios necesitan más profundidad visual.
- La frase legal visible mata parte de la venta.

Dirección:

- Carrusel automático hacia la derecha.
- Tarjetas glass/blur.
- Imagen distinta por testimonio.
- Nombre, contexto y resultado.
- Legal elegante y discreto en footer o microcopy:
  “Historias compartidas por alumnos. Algunos nombres o detalles pueden haberse simplificado para proteger privacidad.”

### Valor gratuito / lead magnet

Unificar:

- “Empieza hoy sin pagar nada”.
- “Tu primera acción clara, gratis”.
- Protocolo 7 días.
- Reto 30 días.
- Comunidad.
- Dossier personalizado.

Debe sentirse como una entrega premium, no como regalos dispersos.

## 11. Programas

### Problema detectado

La página necesita un rediseño fuerte. Hay recursos visuales que no aportan: montaña, dumbbell, partículas, iconos flotantes, textos dentro de cajas pobres. Algunas frases como “mismo estándar” no dicen nada.

### Dirección

Transformar Programas en una página editorial premium:

- Hero claro con imagen cinematográfica.
- Secciones alternas imagen/texto.
- Cada tipo de usuario representado con intención: niños, jóvenes, adultos, atletas.
- Método explicado con visuales propios, no iconos decorativos.
- Bloques menos agresivos en mayúsculas.
- Más claridad de qué incluye cada programa.

### Eliminar o mover

- Servicios adicionales repetidos.
- Calculadora repetida.
- Cards pobres tipo checklist si no aportan.

Eso debe integrarse en el configurador/tienda.

## 12. Planes y presentaciones de plan

### Problema detectado

Los planes han mejorado, pero aún hay problemas:

- Etiquetas/tabs con color mejorable.
- Duplicidad de “preview / experiencia en grande”.
- Cajas de precio rectangulares y poco premium.
- Algunas frases pueden confundir, por ejemplo “primer mes 0 euros”.
- Falta imagen relevante por plan.

### Dirección

Cada plan necesita:

- Imagen o escena propia.
- Beneficio principal claro.
- Para quién es.
- Qué incluye.
- Qué no incluye.
- Precio y condiciones sin parecer agresivo.
- CTA doble:
  - “Ver en web”
  - “Descargar dossier PDF”

## 13. Configurador / servicios / mini-store

### Problema detectado

El configurador, servicios adicionales y calculadora se repiten y se sienten separados.

### Dirección

Unificar en una experiencia tipo tienda elite:

- Selección por categorías.
- Servicios con imagen.
- Añadir/quitar como carrito.
- Resumen tipo recibo premium.
- Créditos aplicables.
- Recomendación inteligente según objetivo.
- CTA final a WhatsApp o compra.

Debe sentirse como:

> “Construye tu plan exacto”

No como:

> “Suma extras en una calculadora”.

## 14. Academia Parkour

### Problema detectado

La página tiene base, pero hay elementos visuales pobres:

- SVG/path/plano feo.
- Cards de edad sin suficiente interacción.
- Niveles con poca vida.
- Método demasiado vacío.
- Logística demasiado grande/plain.

- Cards de edades con flecha y apertura de beneficios.
- Niveles con preview visual/video.
- Método con escenas reales: seguridad, técnica, progresión, confianza.
- FAQ puede quedarse en negro porque funciona, pero debe integrarse mejor.

## 15. BAYONA+ / app

### Problema detectado

La primera parte funciona por minimalismo y espacio, pero después la página se rompe:

- Parece una página privada.
- Se pierde el header/top menu.
- Se pierde el footer o el flujo.
- No conduce bien al siguiente paso.

### Dirección

BAYONA+ debe ser una estación del recorrido, no un producto cerrado.

Copy recomendado:

- “Acceso prioritario”
- “Lista de interés”
- “Vista previa”
- “Funciones en preparación”
- “Tu centro de mando está tomando forma”

Evitar repetir excesivamente “en desarrollo” como si fuera una disculpa. Debe sonar a preventa/early access, no a obra inacabada.

### Modelo de producto

- Free plan: acceso básico, recursos, comunidad, seguimiento simple.
- Suscriptores: funciones avanzadas, análisis, personalización, integración con programas.

### Siguiente paso

Después de BAYONA+ debe ir a tienda/sesiones, no a una ruta inconexa.

## 16. Tienda

### Problema detectado

La tienda se ve funcional pero no suficientemente integrada en el recorrido.

### Dirección

Debe parecer una boutique BAYONA:

- Colecciones claras.
- Productos con imagen consistente.
- Carrito elegante.
- Créditos/cupones visibles como beneficio.
- WhatsApp para dudas.
- Relación con sesiones, servicios y planes.

La tienda no es solo mercancía: también puede ser puerta a sesiones sueltas, evaluaciones, recuperación, clase de prueba, consulta o paquetes.

## 17. FAQ

### Problema detectado

El hero tiene imagen con doble capa/corte extraño. El orden de recorrido puede ser incoherente si FAQ envía al usuario hacia el inicio.

### Dirección

FAQ debe actuar como cierre de confianza:

- Resolver objeciones.
- Aclarar programas, precios, condiciones, seguridad, experiencia previa.
- Llevar a comunidad, tienda o cuenta según el punto del recorrido.
- Mantener el mismo sistema visual.

### Ajuste de navegación

FAQ debería estar cerca del final, antes de cuenta o antes de decisión final.

## 18. Comunidad

### Problema detectado

La página está demasiado oscura y algunas secciones se sienten inconsistentes. El hero centrado no convence del todo. Hay imágenes metidas dentro de cajas cuando deberían ser fondos o mockups.

### Dirección

La comunidad debe sentirse como un club:

- Imagen grande humana.
- Entrada gratuita clara.
- Ritmo semanal claro.
- Mockups/folios en lugar de cajas con imágenes pequeñas.
- Tres niveles representados con tarjetas premium, no cards genéricas.

### Semana / pulso

La línea lunes-miércoles-viernes gusta como idea, pero debe convertirse en un sistema más claro:

- Calendario semanal.
- Pulso semanal.
- Posible calendario mensual.
- Temas por día.
- Qué se comparte.
- Qué recibe la persona.

---

## 19. Recursos

### Lo que funciona

La portada de la revista/folio gusta mucho y debe informar el resto del diseño.

### Dirección

Recursos debe sentirse como una biblioteca premium, no como una sección de “cosas gratis”.

Componentes:

- Biblioteca.
- Revista.
- Dossier.
- Reto.
- Consulta.
- Material descargable.

### Reto 30 días

Debe explicarse mejor:

- Es un workbook/taller de 30 días.
- La persona entrena sola con guía.
- Puede mandar sesiones, fotos, comidas o dudas.
- Puede ganar o desbloquear un programa personalizado.
- Tiene reglas y condiciones claras.
- No se vende como promesa vacía.

### Consulta sobre recursos

Debe sentirse como una consulta gratuita experta:

- El usuario adjunta contexto.
- BAYONA revisa y responde.
- Si requiere profundidad, se deriva a WhatsApp/servicio.

## 20. Entrada / onboarding

### Problema detectado

El onboarding tiene buena idea pero queda demasiado vacío y oscuro. Algunas preguntas no atacan problemas reales. El usuario debe sentir que entra a una casa/gimnasio/club exclusivo.

### Dirección

Primera escena:

- “Bienvenido a BAYONA”
- Sensación de puertas que se abren.
- Imagen cinematográfica de entrada/club/gimnasio/casa.
- Sebastián como anfitrión.

Pasos recomendados:

1. Nombre.
2. Idioma.
3. País/moneda/contexto.
4. Objetivo/problema principal.
5. Ritmo disponible.
6. Presentación del asistente.
7. Inicio del recorrido personalizado.

### Preguntas

Cambiar “¿Qué viniste a construir?” por algo más orientado al problema:

- “¿Qué quieres resolver primero?”
- “¿Qué necesitas recuperar?”
- “¿Qué te gustaría que fuera más fácil dentro de 30 días?”

Opciones más accionables:

- Constancia.
- Fuerza.
- Movilidad.
- Dolor o rigidez.
- Volver a entrenar.
- Aprender parkour.
- Comer mejor.
- Solo estoy explorando.

### No adelantar demasiado

La idea de “tres puertas” es buena, pero no debe aparecer demasiado pronto ni parecer final antes de recorrer el sitio.

## 22. Fases de ejecución

### Fase 0 — Orden y correcciones críticas

Objetivo: que el sitio deje de sentirse roto o incoherente.

Tareas:

- Restaurar header/footer en BAYONA+ y dashboard si se pierden.
- Ajustar siguiente paso de BAYONA+ hacia tienda.
- Revisar “LAS INSTALACIONES” y sustituir/eliminar.
- Crear sistema único para siguiente parada.
- Crear sistema único para línea de progreso.
- Evitar créditos automáticos por scroll.

### Fase 1 — Sistema visual global

Objetivo: unificar estética sin clonar todos los bloques.

Tareas:

- Definir plantillas de sección cinematográfica.
- Definir variantes de imagen/fondo/mockup.
- Rediseñar cards glass.
- Unificar títulos con dos colores.
- Crear transiciones por degradado entre secciones.

### Fase 2 — Recompensas, wallet y cuenta

Objetivo: convertir la navegación en juego premium de descubrimiento.

Tareas:

- Rediseñar wallet.
- Implementar reclamar regalos por clic.
- Guardar estado local de recompensas.
- Crear resumen de recursos ganados.
- Conectar con crear cuenta/dashboard.

### Fase 3 — Home, comunidad y recursos

Objetivo: rehacer las páginas que más definen la marca.

Tareas:

- Home con testimonios nuevos y valor gratuito unificado.
- Comunidad con calendario/pulso semanal.
- Recursos como biblioteca premium.
- Reto 30 días como workbook/taller.

### Fase 4 — Programas, planes y Parkour

Objetivo: hacer vendibles y claros los productos principales.

Tareas:

- Programas con estructura editorial premium.
- Planes con imágenes, PDF/dossier y oferta más clara.
- Parkour con visuales reales, niveles y método mejor presentados.

### Fase 5 — Tienda y configurador

Objetivo: convertir servicios/calculadora en experiencia de compra.

Tareas:

- Mini-store de servicios.
- Recibo premium.
- Créditos/cupones.
- Sesiones sueltas.
- Cierre por WhatsApp o compra.

### Fase 6 — BAYONA+ y dashboard

Objetivo: integrar la app como parte del ecosistema.

Tareas:

- BAYONA+ como lista prioritaria/early access.
- Dashboard premium con recursos/compras/créditos.
- Funciones gratis vs suscriptor.
- Camino hacia pago, WhatsApp o programa.

### Fase 7 — Asistente AI e integraciones

Objetivo: preparar el salto a producto real.

Tareas:

- Asistente BAYONA con personalidad.
- Escalado a WhatsApp.
- Formularios.
- Stripe.
- Login/cuenta.
- Guardado real de recursos.

## 23. Checklist de aceptación final

El rediseño estará bien encaminado cuando:

- No haya páginas que parezcan de otro producto.
- Header, footer, progreso y siguiente paso funcionen en todo el sitio.
- Cada imagen tenga razón de ser.
- Las recompensas se reclamen activamente.
- La wallet parezca premium.
- BAYONA+ no parezca abandonada.
- Tienda sea una boutique/mini-store, no solo una rejilla.
- Recursos parezcan una biblioteca premium.
- Comunidad parezca un club vivo.
- Programas expliquen con claridad qué comprar y por qué.
- La cuenta sea la continuación natural del recorrido.
- WhatsApp y asistente estén claramente diferenciados.
- El usuario pueda terminar diciendo: “entiendo qué es BAYONA, qué gano ahora y cuál es mi siguiente paso”.
